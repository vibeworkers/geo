## Score and evidence terms

| Term | Meaning in this skill |
| --- | --- |
| readiness_signal | A setup condition such as crawler access, schema validity, content readiness, or feed readiness |
| heuristic_signal | A likely but unobserved improvement based on known platform behavior or implementation quality |
| observed_answer | A captured answer where the brand, page, product, or claim appeared |
| observed_citation | A captured answer with a saved source or citation path |
| referral_signal | Analytics or logs showing traffic from a target platform |
| conversion_signal | Analytics, commerce, CRM, or action systems showing qualified conversion evidence |
| confidence ladder | The distinction between high, medium, and low confidence based on evidence quality and recency |
| T0 official | Official platform, product, or standards documentation |
| T1 observed | Directly captured answer, citation, referral, or conversion evidence |
| T2 inferred | Reasonable interpretation from readiness or heuristic evidence |
| T3 speculative | Unverified claim that must be marked `확인 필요` or TODO |
| measurement status | not measured, ready to measure, observed_answer, observed_citation, referral_signal, or conversion_signal |
| commerce readiness | product/schema, merchant, catalog/feed, checkout/action, measurement, and platform eligibility status |
| private surface | connector, logged-in account, personalized, or user-provided context that cannot prove public visibility |
| regional context | country, language, local platform, vertical, or market condition that can change the GEO recommendation |
| policy risk | robots, terms, privacy, regulated claims, brand claims, or commerce eligibility status |

## Editing defaults

- Prefer `working-source` for direct GEO content changes.
- Prefer `evidence-note` for status, justification, or validation claims.
- Prefer `asset-surface` for reusable learner or operator materials.
- Prefer `execution-bundle` for repo-local audit, schema, compare, or report execution after `skills/*` is confirmed.
- Ask short pre-questions first when `goal / scope / surface / success / evidence target` is still unclear.
- Keep stored prompts and routing examples in English.
- Ask for Korean or English conversation language at first session start and
  apply it only to LLM conversation.
- Accept `geo language Korean|English` and `$geo language Korean|English` for
  mid-session conversation-only language changes.
- Treat `derived-deliverable` as publishable output, not as the first edit
  target.
